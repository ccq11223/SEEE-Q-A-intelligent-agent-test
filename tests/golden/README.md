# 黄金测试集

**这是整个项目里最重要的基础设施。** 没有它，判断「这次调教是变好了还是变坏了」
只能凭感觉——改一句提示词、换一个模型、补一份资料，都可能让某些问题从能答变成乱答，
而你不会立刻发现。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `qa.jsonl` | 正式题集，一行一题。**这个文件要纳入 git** |
| `report.md` | 最近一次运行的结果（自动生成，不入 git） |
| `candidates.jsonl` | 从课件里自动生成的候选题草稿（`scripts/suggest_golden.py` 产出，待你审核） |

## 题目格式

一行一个 JSON 对象：

```json
{"id": "circuit-001", "question": "替代定理的适用条件是什么？", "negative": false, "expect_pages": [25, 26], "expect_points": ["原电路与替代后电路都必须有唯一解", "替代后不能有电压源回路", "替代后不能有电流源节点"], "chapter": "第4章 电路定理", "source_doc": "slide-07", "notes": "", "status": "ready"}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✅ | 唯一标识，建议 `circuit-001` 这种格式 |
| `question` | ✅ | 学生会怎么问。**用学生的大白话写**，不要用课件里的书面语——否则测不出真实效果 |
| `negative` | ✅ | `true` = 资料里**根本没有**这道题。这类题是整套测试里价值最高的 |
| `expect_pages` | 正样本必填 | 期望命中的页码。**这里填的是「哪一页有答案」**，不是「最终回答里会引用哪页」 |
| `expect_points` | 建议填 | 期望的结论要点，人工复核原文时用 |
| `chapter` | 选填 | 便于按章节统计薄弱环节 |
| `source_doc` | 选填 | 答案在哪个 `doc_key` 里 |
| `notes` | 选填 | 备注，比如「这题学长说学生最容易问」 |
| `status` | 选填 | `ready`（默认，参与计分）或 `draft`（草稿，不参与计分） |

**两条硬性约束**（写错会直接报错，不会静默放过）：

1. **正样本必须有 `expect_pages`。** 没填就没法判断检索对不对，那这题就是废的。
2. **负样本的 `expect_pages` 必须为空。** 它本来就是资料里没有的题，不该期望命中任何页。

## 建题集的四个要求（方案 §8.1）

1. **30-50 题**，覆盖课程的核心章节；
2. **必须包含 10 道 `negative: true` 的负样本**——测的是「系统会不会编造」，
   这是《张导_智能体小思考.docx》最关心的风险；
3. `question` 用学生的口语来写，不要抄课件标题；
4. 负样本要**选得像真问题**（学生真的可能问），而不是「量子力学是什么」这种一眼假的。

### 负样本怎么挑

**从课件覆盖不到的地方挑。** 你的 19 份资料覆盖第 1、2、3、4、7、8、10-15、20、21 章，
所以第 5、6、9、16-19 章的内容天然是负样本的好素材：

```json
{"id": "neg-001", "question": "回转器怎么用在有源滤波器设计里？", "negative": true, "chapter": "（资料未覆盖）", "notes": "实测已验证：检索最高分 0.627，模型如实回答「现有资料没有覆盖」", "status": "ready"}
```

**挑完要用检索验一遍**：跑 `python -m pipeline golden --only-retrieval`，
看每道负样本的「最高相关度」。如果某道负样本的相关度很高（比如 > 0.6），
说明资料里其实有相关内容，它就不是合格负样本，该换掉。

## 怎么用

```powershell
# 1. 先校验题集格式（不联网、不花钱）
python -m pipeline golden --check

# 2. 只测检索命中率（最便宜：只调用向量模型，不调用生成模型）
python -m pipeline golden --only-retrieval

# 3. 完整跑一遍（检索 + 生成 + 引用校验 + 转人工判定）
python -m pipeline golden

# 4. 只看某几题
python -m pipeline golden --only neg-001 --show 5
```

输出的报告写在 `tests/golden/report.md`，包含四个指标：

| 指标 | 目标 | 含义 |
| --- | --- | --- |
| **检索命中率** | ≥ 80% | 正样本里，期望页码被检索到的比例 |
| **编造率** | ≤ 5% | 负样本里，既答了又没说「资料里没有」的比例 |
| **引用有效率** | 100% | 回答里的页码全部真实存在 |
| **转人工率** | — | 负样本里走转人工分支的比例（越高越保守，但诚实说明缺口的回答也是合格的） |

退出码非 0 表示有指标不达标，可以直接用在脚本或 CI 里。

## 什么时候跑

**每次改动下面任何一处之后，都要跑一遍**，并记录结果：

- 改 `config/prompts.yaml`（提示词）
- 换 `config/models.yaml` 里的模型
- 改 `config/retrieval.yaml`（阈值、召回条数）
- 往知识库补了新资料
- 改了切块参数（`config/pipeline.yaml` 的 `chunking`）

## 错题闭环

发现 AI 答错时（学生反馈、或你自己发现）：

1. 记进 `error_ledger` 表；
2. 修正知识库内容或提示词；
3. **把这道题加进 `qa.jsonl`** —— 这是最容易被忽略、但价值最高的一步。
   加了之后，以后每次改动都会自动回归验证，同一个错误不会再犯第二次。
