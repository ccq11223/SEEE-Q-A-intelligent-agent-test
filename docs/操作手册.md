这是一份**照着做**的清单：每一步都写清了在哪里点、粘贴什么、跑什么命令、

## 第 1 步　开通 Supabase 并建表

> 这一步可以晚点做。第 2-10 步全部能在不连数据库的情况下跑通。
> 但既然迟早要做，建议一次做完，避免回头补。

### 1.1 建项目

1. 浏览器打开 <https://supabase.com>，点 `Start your project`，用 GitHub 账号或邮箱注册并登录。
2. 进入控制台后点 `New project`，填写：
   - `Name`：填 `seeq-kb`
   - `Database Password`：点右侧 `Generate a password`，**然后把这串口令复制到记事本存好**，后面还要用
   - `Region`：选 `Southeast Asia (Singapore)` 或 `Northeast Asia (Tokyo)`，国内访问延迟较低
3. 点 `Create new project`，等 1-2 分钟，直到左边栏出现 `Table Editor`。

### 1.2 粘贴建表脚本

1. 左侧栏点 `SQL Editor` → 右上角 `New query`。
2. 用记事本打开 `db\migrations\001_init.sql`，**全选复制**，粘贴到 SQL 编辑框。
3. 点右下角 `Run`（或按 `Ctrl+Enter`）。下方出现 `Success. No rows returned` 即成功。
4. 再点 `New query`，同样方式执行 `db\migrations\002_seed.sql`，然后 `003_qa_log_view.sql`。
5. 左侧栏点 `Table Editor`，应该能看到 12 张表：
   `chunks`、`courses`、`diagnostics`、`diagnostic_items`、`diagnostic_sets`、
   `documents`、`error_ledger`、`gaps`、`parse_errors`、`qa_logs`、`questions`、`student_sessions`。

✅ **检查点**：Table Editor 里 12 张表齐全，`courses` 表里有 1 行「电路理论（上）」。

### 1.3 拿到数据库连接串

1. 点控制台右上角的 `Connect` 按钮（有的版本在项目名旁边的齿轮/Connect 处）。
2. 选 `Connection string` → `URI` 标签页。
3. 复制那串以 `postgresql://postgres.` 开头的地址。
4. 把其中的 `[YOUR-PASSWORD]` 替换成 1.1 步生成的口令，得到形如：

```
postgresql://postgres.abcdefgh:你的口令@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres
```

> **口令里只有 4 个字符需要处理**：`/`、`@`、`%` 和空格，分别写成
> `%2F`、`%40`、`%25`、`%20`。
> 其余字符（包括 `-`、`_`、`.`、`~`、`:`、`#`）都能直接用，不用转义。
> 拿不准就回 1.1 步用 `Generate a password` 重新生成一串纯字母数字的口令。
> 反正第 5 步的 `doctor` 会替你把连接串体检一遍，不用靠记。

先存到记事本，第 5 步要用。

```powershell
python -m pipeline keys
```

```

---------  -------------------  --------  -----------------------

```

它一次能查出三类问题：密钥无效（`鉴权失败`）、**把别家的密钥填到了这一行**、
以及配置里的模型名这个账号用不了（会提示「列表里没有 xxx」）。

**密钥有效 ≠ 能用。** 如果密钥对、但模型名不在账号的可用列表里，命令会明确说
「问题只在模型名」并列出可照抄的候选名，同时返回非 0 退出码。这种情况不解决的话，
建库会在解析阶段**整份失败**，而且报错是 HTTP 403 Access denied，看起来像权限问题。

想直接看某个平台的全部可用模型名：

```powershell
# 列出全部（176 个会刷屏，一般配合 --grep 用）
python -m pipeline keys --role vision --list

# 只看名字含 vl 的多模态模型
python -m pipeline keys --role vision --list --grep vl
```

> 用 `--grep` 而不是 `| Select-String`：管道会让 PowerShell 用控制台代码页
> 重新解码 Python 的输出，中文会变成 `鍙敤` 这种乱码。`--grep` 在程序内部过滤，
> 不经过管道，所以不会乱码。

## 第 6 步　把资料放进 `data\raw\`

```powershell
explorer data\raw
```

把这一门课的原始文件全部复制进去。几条建议：

- **文件名保持可读**。像 `电路理论串讲课件_第1章.pptx` 这样，比 `1.pptx` 好得多——
  后面的自动登记会靠文件名猜资料类型。
- **同一份文件只放一次**。重名文件会让登记步骤不好判断。
- **不要放压缩包、视频、Excel 题库**。当前支持：
  PDF、PPTX/PPT、DOCX/DOC、图片（png/jpg/webp）、Markdown、纯文本。
- **Word 文档先关掉**。开着的话 Windows 会锁定文件，转换会失败。

✅ **检查点**：`data\raw` 里有你要用的全部课件，没有 `~$` 开头的临时文件。

### 人工确认什么

程序只做草稿，**类型和可信级别必须你亲自过一遍**。打开台账，重点看两件事：

**① `doc_type` 对不对。** 可选项只有这七个：

| doc_type | 含义 |
| --- | --- |
| `textbook` | 课本重点 |
| `slide` | 串讲 PPT / 课件 |
| `exam_scope` | 老师划定的考点范围 |
| `example` | 典型例题 |
| `past_exam` | 往年题（题干+答案） |
| `past_exam_solution` | 往年题解析 |
| `web` | 网络资料 |

**② `trust_level` 对不对。** 只有三档，这一列决定了 AI 敢不敢引用：

| trust_level | 含义 | 能否被引用 |
| --- | --- | --- |
| `1` | 课本重点、老师划定考点、中心往届串讲 PPT | 可以直接引用 |
| `2` | 典型例题、我们生成的往年题解析 | 可以引用，但须标注 |
| `3` | 网络来源 | **不能直接引用**，须先审核升级 |

程序给的默认值就是按上表来的。要改的直接在记事本里改数字/单词即可。

改完**顺手把 `notes` 里的「自动登记，待人工确认类型与级别」删掉**——
这样一眼就能看出哪些行还没人看过。

一个改完了的例子：

```csv
doc_key,course_id,doc_type,trust_level,filename,title,term,priority,notes
slide-01,circuit-theory-1,textbook,1,a1b2c3.pdf,教材重点 第1章,2026秋,2,这本其实是教材扫描件
slide-02,circuit-theory-1,slide,1,电路理论串讲课件_第1章.pptx,第1章 电路模型与电路定律,2026秋,1,
```

复核一遍：

```powershell

```

✅ **检查点**：每份资料都显示 `已就位`，没有 `缺文件`；类型和级别你都能说出理由
（例如「这份是中心往届串讲，所以是一级」）。

## 第 8 步　先跑 5 页试水（**这一步不能跳过**）

挑一份最有代表性的课件（含公式、含电路图的那种）：

```powershell
python -m pipeline run --doc slide-02 --pages 1-5 --dry-run
```

跑完打开解析结果：

```powershell
notepad data\work\slide-02\doc.md
```

同时打开原始课件对照着看。**只看三件事**：

| 看什么 | 合格的样子 | 不合格的样子 |
| --- | --- | --- |
| 公式 | `$\sum_{k=1}^{n} i_k = 0$` | `∑ k=1 n ik = 0`、缺下标、公式整段消失 |
| 表格 | Markdown 表格，有表头 | 表格被压成一长串文字 |
| 图 | `[图 第1页-1：电路节点示意]` | 图里的关键信息（标注、数值）完全没提 |

**为什么不跳过**：解析质量是整个系统的天花板。如果这里发现某一类公式全部转错，
那就是系统性问题——该换模型或换参数重跑，而不是逐页手工修。试水只花几分钱。

发现问题时先看这张表：

| 现象 | 先检查 |
| --- | --- |
| 整页内容和原图不符 | 是不是 `parsing.mode` 被改成了 `hybrid`（默认 `vision`，每页都送图） |
| 公式全部变成乱码 | 用的是 PDF 还是 PPT？如果是扫描件 OCR 反而更准，考虑换解析路线 |
| 某一页整个是 `[本页解析失败…]` | 单独补跑这页：`python -m pipeline parse --doc slide-02 --pages 7` |
| 输出里出现中文乱码 | 看输出编码，`config/prompts.yaml` 是否被记事本存成了 ANSI |

✅ **检查点**：公式、表格、图片三类内容都能对上，你愿意拿这份解析结果去做答疑。
不满意就调 `config/pipeline.yaml` 或 `config/models.yaml` 重跑 ——
缓存键包含提示词版本与模型名，改了会自动重跑，没改的页不会重复花钱。

## 第 9 步　全量建库

```powershell
python -m pipeline run --all
```

屏幕上的进度长这样：

```
=== slide-02 · 第1章 电路模型与电路定律（一级 · 权威（可直接引用））===
  [2/6] 渲染完成：42 页（powerpoint-com）
  [3/6] 解析 5/42 页
  [3/6] 解析 10/42 页
  ...
  [3/6] 解析完成：共 42 页｜缓存命中 0 页｜含公式 31 页｜图片占位 12 个｜不清晰标记 0 处｜失败 0 页
  [5/6] 切块完成：58 块
  [6/6] 向量化 40/58 块
  [6/6] 向量化完成：58 条
  [6/6] 入库完成：58 块 → local
=== 小结：42 页｜解析 42 页（失败 0）｜58 块｜入库 58 ===
```

**耗时预期**：1000 页资料，机器跑 1-3 小时。视模型并发限制，可能更久。

**中途断了怎么办**：直接重新执行同一条命令。已经解析过的页会命中缓存，不会重复花钱。

**只想看看不花钱**：加 `--dry-run`，只产出本地文件，不写知识库。

✅ **检查点**：每份资料的小结里都没有 `失败 > 0`，也没有「已跳过」的提示。

## 第 10 步　人工抽查 5%

```powershell
python -m pipeline sample --all
```

输出形如 `slide-02：抽查 3 页 → data\work\slide-02\sample_report.md`。

打开报告：

```powershell
notepad data\work\slide-02\sample_report.md
```

报告会**按风险排序**列出该看哪几页，以及每页的图片路径和解析文本，你对着看就行。
排序的优先级是：解析失败的页 → 有「不清晰」标记的页 → 同时含公式和图表的页 →
含公式的页 → 含图片占位的页 → 随机抽查。

**抽查的目的是发现系统性错误，不是逐页校对。**
如果同一类错误出现三次以上，说明是系统性问题，换参数重跑整个文档，不要逐页手工修。
发现的问题记下来（页码 + 错误类型 + 一句描述），后续填进 `parse_errors` 表。

✅ **检查点**：存在一份 `sample_report.md`，并且你确实抽出时间看过了重点页。

也可以到 Supabase 的 `Table Editor` → `chunks` 表里亲眼看到数据。

✅ **检查点**：`stats` 里的份数和块数和你实际处理的资料对得上，
Supabase 的 `chunks` 表里有行。

## 第 12 步　提问验收

先看检索能不能命中正确页码：

```powershell
python -m pipeline search "节点电压法的适用条件"
```

输出：

```
问题：节点电压法的适用条件
最高相关度：0.612｜判定：有依据

  2. [0.556] 第 19 页｜2.3 节点电压法｜以节点电压为未知量，对独立节点列 KCL 方程…
```

再走一遍完整决策链：

```powershell
python -m pipeline ask "为什么理想电流源不能开路？"
```

输出会写清走了哪条分支：

```
模式：kb｜最高相关度 0.588｜引用页码 [12, 13]

（回答正文，每个结论后面都带「第 X 页」）

--- 引用到的内容块 ---
  1. 第 12 页｜1.4 理想电源｜0.588
```

- `模式：kb` = 有依据，正常回答；
- `模式：handoff` = 没依据，转人工，同时这个问题进了知识缺口清单。

**这两个结果都是对的。** 故意问一个资料里没有的问题（比如「回转器怎么用」），
如果它老老实实回 `handoff` 而不是硬编一段，说明系统在按设计工作。

## 第 13 步　建黄金测试集（最容易被跳过、但价值最高）

在 `tests\golden\` 下建一个 `qa.jsonl`，每题一行：

```json
{"question": "节点电压法的适用条件是什么？", "expect_pages": [18, 19], "expect_points": ["支路多、节点少", "以节点电压为未知量列 KCL"], "negative": false}
{"question": "回转器怎么用？", "expect_pages": [], "expect_points": [], "negative": true}
```

凑够 30-50 题，**其中必须有 10 道 `negative: true` 的负样本**（资料里根本没有的）。

以后每次改提示词、换模型、补资料之后，都跑一遍这个题集并记录命中率与编造率。
这是判断「这次调教是变好了还是变坏了」的唯一客观依据。

## 附录 B　出错对照表

| 报错或现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `缺少环境变量 DASHSCOPE_API_KEY` | `.env` 没填或没保存 | 填好 `.env` 再跑；注意不要加引号 |
| `embedding 缺少 SILICONFLOW_API_KEY` | `SILICONFLOW_API_KEY=` 后面是空的 | 去硅基流动建一个密钥填上；填完用 `python -m pipeline keys` 验证 |
| `keys` 报「鉴权失败」 | 密钥无效，或把别家的密钥填到了这一行 | 每个密钥只能填在它自己那一行；`keys` 会指出是哪个变量 |
| `keys` 说「密钥有效，但列表里没有 xxx」 | 模型名对不上（不是密钥问题） | 按它列出的候选名改 `config/models.yaml`；改完再跑 `keys` 确认 |
| `run` 里整份资料全页 403 失败，但 `keys` 说密钥有效 | 模型名不在账号可用列表里 | 同上：换模型名，不是换密钥 |
| `keys` 报「网络不通」 | 命令行出不了网（浏览器能打开不代表命令行能通） | 检查代理/防火墙；公司网络常拦命令行直连 |
| 两行的密钥值一模一样 | 复制粘贴时粘错行 | 逐行核对；用不到的（如 TAVILY）留空比填错好 |
| `缺少列：xxx` | 台账表头被改坏了 | 表头必须是：`doc_key,course_id,doc_type,trust_level,filename,title,term,priority,notes` |
| `台账第 N 行：doc_type=xx 不认识` | 类型拼错 | 只能填那七个英文值，见第 7 步的表格 |
| `找不到原始文件` | 文件名对不上 | 让 `data\raw` 里的文件名与台账 `filename` 列完全一致 |
| `无法启动 PowerPoint 自动化` | 没有 PowerPoint / 文件被占用 / 在无界面环境运行 | 关掉正在编辑的 PPT；或在 PowerPoint 里另存为 PDF 后改台账 `filename` |
| `存在未解析页，已跳过切块与入库` | 有页解析失败 | 这是保护机制。按提示补跑那几页；确认是空白页再用 `--allow-partial` |
| `第 1 条向量维度是 768，但配置里写的是 1024` | 换了向量模型 | 同步改 `config/models.yaml` 的 `embedding.dim` 与 `db/migrations/001_init.sql` 的 `vector(N)`，并重建 |
| `引用校验未通过` 反复出现 | 模型爱编页码 | 先看提示词是否被改坏；仍不行就换生成模型（见云平台文档第五节） |
| 解析结果里出现 `[本页解析失败：… HTTP 403 … Access denied]` | 百炼密钥被拒：不是国内站密钥 / 未启用 / 账号未开通该模型 / 欠费 | 先跑 `python -m pipeline keys`；再去百炼控制台核对密钥状态与欠费。完整报错在 `data\work\<编号>\parse_errors.json` |
| 整份资料**每一页**都失败 | 不是单页问题，是密钥、额度或网络 | 别去挑某一页看；`run` 现在会按原因归类打印，先解决那个原因 |
| `已解析的 N 页里有 M 页失败（超过质量闸门）` | 质量闸门生效，拦住了「把满篇解析失败标记切成块写进知识库」 | 修好原因后重跑。确认要带着失败页入库，才加 `--allow-partial` |
| 解析失败后重跑，那几页会重新花钱吗 | 不会重复花：只有解析**成功**的页才写缓存 | 失败页会自动重试，成功页走缓存 |
| `连接串体检未通过：「用户@主机」这一段里出现了 2 个 @` | 口令含未转义的 `@` | 把 `@` 写成 `%40`，或改用不含 `/ @ % 空格` 的口令 |
| `连接串体检未通过：这一段里找不到 @` | 口令含未转义的 `/`，把主机名截掉了 | 把 `/` 写成 `%2F` |
| `连接串无法解析：invalid percent-encoded token` | 口令含未转义的 `%` | 把 `%` 写成 `%25` |
| 报错说口令认证失败，但口令明明是对的 | 口令里的 `@` 让主机名被悄悄改了 | 跑 `python -m pipeline doctor`，看「解析结果」里的主机名对不对 |
| 中文变成 `鍙敤` 这类怪字 | 输出被管道（`\| Select-String`）按控制台代码页重新解码 | 用命令自带的 `--grep` 代替管道；或先跑 `. .\scripts\setup-console.ps1` |
| 中文变成 `��;` 这类怪字 | 控制台代码页与 Python 输出编码不一致 | 同上：每开一个新窗口先跑 `. .\scripts\setup-console.ps1` |
| `doctor` 里的对勾显示成 `OK` | 终端编码装不下 `✓`，程序自动退化成 ASCII | 正常现象，不影响判断；想要对勾就先 `chcp 65001` |
