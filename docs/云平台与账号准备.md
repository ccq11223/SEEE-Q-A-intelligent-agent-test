# 云平台选型与账号准备

对应实施方案 §3 技术选型与 §6 部署方案。这份文档回答两个问题：
**用哪一家云、我需要开通哪些账号。**

---

## 一、结论先说

| 用途 | 选哪家 | 为什么是它 | 需要产出的凭证 |
| --- | --- | --- | --- |
| 云端数据库（含向量、账号、后台） | **Supabase** | 免费层同时给到 PostgreSQL + pgvector + 网页表编辑器 + 内置账号系统。方案 §2.4 的 D3「知识库放云端、维护者用账号、学生用链接」用一家服务就能落地，不用拼三个组件 | `SUPABASE_DB_URL` |
| 课件视觉解析（图片 → Markdown/LaTeX） | **阿里云百炼（DashScope）** | 中文课件和公式识别是它最强的地方，国内节点延迟低，接口是 OpenAI 兼容格式，有免费额度可以先试 | `DASHSCOPE_API_KEY` |
| 向量化 | **硅基流动（SiliconFlow）的 `BAAI/bge-m3`** | BGE-M3 是中文检索里最稳的开源向量模型之一（1024 维），SiliconFlow 提供 OpenAI 兼容接口且有免费额度 | `SILICONFLOW_API_KEY` |
| 生成模型（答疑作答） | **DeepSeek `deepseek-chat`** | 便宜、中文稳定。方案要求"一学期大模型支出 ≤ 100 元"，它是最容易达成的 | `DEEPSEEK_API_KEY` |
| 联网兜底搜索（阶段 2，可选） | **Tavily** | 返回结构化结果，比自己抓网页省事。默认关闭，不配也能跑 | `TAVILY_API_KEY` |
| 在线服务托管（阶段 2，可选） | 先用 **Cloudflare Tunnel**，稳定后换国内轻量云服务器 | 试点期不必备案（方案 §6.2），等真要面向全年级再走备案 | — |

**一句话：数据库用 Supabase，模型用「百炼 + 硅基流动 + DeepSeek」三家拼装。**

四家全部有免费额度或极低单价，整套跑起来的**现金支出约等于 0**，
真实成本主要是 DeepSeek 那几元到几十元的调用费。

## 二、为什么不选别的

**为什么不用 Dify / FastGPT / RAGFlow 直接搭一个？**
方案 §2.4 的 D1 已确定自研。更实际的原因是本项目的决策链有硬性定制：
引用页码强校验、双模型交叉校验、复杂题强制转人工、知识缺口回写。
现成平台改这些的代价高于自己写这四处代码（方案 §3.6）。
它们的源码值得读，但不部署。

**为什么不用 Pinecone / Weaviate / MongoDB Atlas？**
pgvector 和数据库同源，少一个组件、少一份账号、少一处计费。
本项目 11 张表之间全是外键关系（资料 → 内容块 → 题目 → 诊断 → 日志），
关系型数据库天然合适；纯向量库反而要在应用层维护这些关系。
数据量到千万级或检索延迟成为瓶颈时，再引入 Qdrant（方案 §3.4 已列为备选）。

**为什么数据库不直接放自己电脑上？**
方案 §1.2 的目标之一是"多人共同维护"。数据库在云端，其他成员不用装任何东西，
登录后台网站就能看报告、提错题。放本地就只有你一个人能维护。

**什么时候该换掉 Supabase？**
如果实测学生端访问延迟高到影响使用，切到国内轻量云服务器自建 PostgreSQL + pgvector
（约 30-60 元/月，方案 §6.3）。切换成本很低：`db/migrations/001_init.sql`
在标准 PostgreSQL 15 上一样能跑，只需要把 `SUPABASE_DB_URL` 换成自建库的连接串。

## 三、账号开通清单（按顺序做）

四家都注册完大约需要 20 分钟。每一步都写清了"产出什么、填到哪"。

### 1. Supabase（云端数据库）

1. 打开 <https://supabase.com> → `Start your project`，用 GitHub 或邮箱注册；
2. `New project`：名字随意（如 `seeq-kb`），区域选**离你最近**的
   （Singapore / Tokyo 对国内延迟较低），数据库口令自己设一个强口令并**记下来**；
3. 等 1-2 分钟初始化完成；
4. 左侧 `SQL Editor` → `New query`，把 `db/migrations/001_init.sql` 全文粘进去 → `Run`；
   再把 `002_seed.sql`、`003_qa_log_view.sql` 依次执行；
5. 到 `Table Editor` 确认能看到 12 张表；
6. 右上角 `Connect` → `Connection string` → `URI`，复制那串
   `postgresql://postgres.xxxx:...@...pooler.supabase.com:5432/postgres`，
   把口令部分替换成第 2 步设置的口令；
7. 写进 `.env` 的 `SUPABASE_DB_URL=...`。

> 注意：流水线用的是**数据库直连串**（能写），将来在线服务用 Supabase 的
> 公开 API Key（只读 + 行级安全）。两套凭据不要混用。

### 2. 阿里云百炼（视觉解析）

1. 打开 <https://bailian.console.aliyun.com>，用支付宝/淘宝账号登录并完成实名；
2. 左侧 `API-KEY` → `创建我的 API-KEY`；
3. 在 `模型广场` 里确认能看到 `qwen-vl-max`（视觉理解）；
4. 写进 `.env` 的 `DASHSCOPE_API_KEY=...`。

> 新账号通常有免费额度。视觉模型按图片 token 计费，
> 1000 页 PPT 一次性解析大约在**几元到二十元**量级（方案 §6.3）。
> 先跑 `--pages 1-5` 试水，确认公式还原效果再全量跑。

### 3. 硅基流动（向量化）

1. 打开 <https://cloud.siliconflow.cn> 注册；
2. 左侧 `API 密钥` → `新建 API 密钥`；
3. 在 `模型广场` 搜索 `BAAI/bge-m3`，确认可用（1024 维）；
4. 写进 `.env` 的 `SILICONFLOW_API_KEY=...`。

> **换向量模型必须重建整个知识库**：数据库里 `chunks.embedding` 是 `vector(1024)`，
> 维度不一致会直接报错（代码里有专门的检查）。要换模型，改
> `config/models.yaml` 的 `embedding.dim` 和 `db/migrations/001_init.sql` 里的
> `vector(N)`，然后删掉 `data/work/*/chunks.jsonl` 之前的向量重跑 `load`。

### 4. DeepSeek（生成）

1. 打开 <https://platform.deepseek.com> 注册；
2. `API keys` → 创建一个；
3. 写进 `.env` 的 `DEEPSEEK_API_KEY=...`。

> 充值 10 元就够试点期用很久。日常答疑一次问答大约 0.01-0.02 元（方案 §6.3）。

### 5.（可选）Tavily 联网搜索

阶段 2 的联网兜底才用得到，现在不配也没关系——`config/retrieval.yaml` 里
`allow_web: false`，系统遇到没覆盖的问题一律转人工，这正是我们想要的第一版行为。

## 五、换服务商要改哪里

所有模型调用都走 OpenAI 兼容的 HTTP 接口，**换服务商只改 `config/models.yaml` 三行**：

```yaml
vision:
  name: qwen-vl-max-latest                                    # ← 模型名
  base_url: https://dashscope.aliyuncs.com/compatible-mode/v1  # ← 服务地址
  api_key_env: DASHSCOPE_API_KEY                              # ← 密钥变量名
```

代码不需要动。备选方案：

| 位置 | 备选 | 切换方式 |
| --- | --- | --- |
| 视觉解析 | 智谱 `glm-4v-plus`：`https://open.bigmodel.cn/api/paas/v4` | 改上面三行 |
| 视觉解析 | 硅基流动 `Qwen/Qwen2.5-VL-72B-Instruct`：`https://api.siliconflow.cn/v1` | 改上面三行 |
| 向量化 | 阿里云百炼 `text-embedding-v3`（1024 维）：`https://dashscope.aliyuncs.com/compatible-mode/v1` | 改上面三行 |
| 生成 | 阿里云百炼 `qwen-plus` | 改上面三行 |
