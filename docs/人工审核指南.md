# 人工审核指南

建库流水线里唯一不能自动化的一步。**核心原则：不要翻 844 页，只看机器挑出来的那一小撮。**

当前实测：844 页里只有 **19 页**需要人工确认。

---

## 一、两层流程

### 第一层：机器筛查（免费，约 1 分钟）

```powershell
python scripts/check_coverage.py --all --report '审核工作单.md'
```

它把每一页的**原文文字层**和**解析结果**比对，只把可能漏了内容的页写进工作单。
它做三件事：

1. **数字覆盖率**——原文里的 1000、314、0.5 这些数值还在不在。
   电路课里丢一个数值就可能答错，所以数字丢一条就算问题。
2. **中文串覆盖率**——原文里连续 3 个以上的汉字还找不找得到。
3. **差异分级**——把「模型改顺了笔误」和「整段真的不见了」分开报，
   避免你在误报上浪费时间。

### 第二层：人看工作单（19 页，约 20 分钟）

```powershell
code '审核工作单.md'
```

（用 VS Code 打开，里面的图片路径可以直接点；用记事本也行。）

每页从上往下是三段，对照着看：

1. **机器判读**——两个覆盖率 + 差异明细
2. **原页图片路径**
3. **原文文字层** 和 **解析结果** 两个折叠块

---

## 二、每页怎么判

| 机器判读 | 含义 | 你要做什么 |
| --- | --- | --- |
| 【待抽查】 | 有差异但重合度高，括号里已经给出解析里长得像的内容 | 扫一眼括号里的提示即可。**多数是模型把原文笔误改顺了**（「电流的取关联参考方向」→「电流的关联参考方向」）、**或繁体字形写成简体**（暫态分量 → 暂态分量）。直接放过 |
| 【疑似缺失】 | 那段原文在解析结果里基本找不到 | **重点看**：打开原页图片，确认它是不是真的不在解析结果里 |
| 数字缺失 | 原文里的某个数值没出现在解析结果里 | 去原图找那个数字。注意两种正常情况：`10^6` 这种上标在 PDF 文字层里会显示成 `106`；页码会被模型按规则正确丢弃 |

### 想直接看原页图片

```powershell
# 办法一：VS Code 打开工作单，点击图片路径
code '审核工作单.md'

# 办法二：命令行打开某一页（改这两行变量）
$d = 'slide-01'; $p = 14
Invoke-Item "data\work\$d\pages\${d}_page_$($p.ToString('0000')).jpg"
```

## 三、判完的三种结论

| 结论 | 动作 |
| --- | --- |
| 内容都在，只是措辞被润色 | **什么都不用做** |
| 确实漏了内容 | 用**补漏命令**（见下）自动补上，补不上的再手工补进页文件 |

### 补漏：让模型再找一遍漏

**这是发现遗漏之后的首选修法，比手工补省事。**

第一遍转写会稳定地漏掉同一类东西：**图上的短标签、口诀、图内的数值、例题的最终答案**——
模型在做「提纲式转写」而不是逐行照抄。而且 `temperature=0`，**重跑一遍结果完全一样**，
所以直接重解析没用。

补漏做的是另一件事：把**原图**和**已有转写结果**一起给模型，只让它找漏。

```powershell
python -m pipeline recall --doc slide-06 --pages 35
python -m pipeline chunk --doc slide-06      # 补完必须重新切块
```

实测效果（真实案例）：

| 页 | 补漏补上的内容 |
| --- | --- |
| slide-06 第 35 页 | U₂=4.86V、U₃=0.86V、I₁、I₂ —— **例题答案整个补回来** |
| slide-15 第 8 页 | 「加强型耦合」「削弱型耦合」两个图注 |
| slide-06 第 37 页 | 「注：与电流源串接的电阻不参与列方程」 |
| slide-19 第 25 页 | 「三要素法」「彼德生法确定」 |

补漏内容追加在页文件末尾，带一行标记 `<!-- 以下内容由补漏校对补上 -->`，
方便一眼看出哪些是补的。

**三道防护**（都是踩过坑之后加的）：

| 防护 | 防的是什么 |
| --- | --- |
| 去重 | 模型会把已有内容再列一遍。实测某页补漏返回 10 行、其中 8 行是原有公式。现在按整行归一化比对（忽略空白、LaTeX 标记、标点、大小写），已有的不重复加 |
| 过滤噪声 | 空 `$$` 块、单个符号、孤立页码，以及模型的自言自语（「等等，以上其实已在已有结果中」）一律丢掉 |
| 异常膨胀拦截 | 补漏结果超过已有内容的 60%、或超过 40 行时**不自动写入**，只提示人工看。实测某页补漏返回 98 行、大半是模型的自我分析 |

补漏不理想时，重新解析那一页（走缓存、不花钱）即可**清掉补漏块**恢复干净，再手工补：

```powershell
python -m pipeline parse --doc slide-01 --pages 26   # 缓存命中，0 成本
notepad data\work\slide-01\pages\slide-01_page_0026.md
```
| 拿不准 | 记进 `parse_errors` 表，交给更熟悉这门课的人确认 |

### 重新解析被挑出的页

**只跑这些页，不是整份资料，花费很小。**

```powershell
# 列出所有需要重跑的页（自动生成命令）
python scripts/check_coverage.py --all --fix-commands

# 按它打印的命令逐条执行，例如
python -m pipeline parse --doc slide-01 --pages 14,26
python -m pipeline chunk --doc slide-01
```

改过提示词之后，**版本号一变缓存自动失效**，重跑时会用新提示词，不需要手动清缓存。

## 四、抽查（另一件不同的事）

上面的 `check_coverage.py` 查的是「**有没有漏内容**」。
还有一类问题它查不出来：**内容没漏，但转写错了**（公式抄错、图看错）。

```powershell
python -m pipeline sample --all
```

生成 `data\work\<编号>\sample_report.md`，按风险排序列出该看哪几页：
解析失败的页 → 有「不清晰」标记的页 → 同时含公式和图表的页 → 含公式的页 →
含图片占位的页 → 随机抽查。

**这类抽查的重点是 `[图上文字]` 标记多的页**——那些内容是从图上读出来的，
没有文字层可以交叉验证，只能靠眼睛。

抽查的目的不是逐页校对，而是发现**系统性错误**：同一类错误出现三次以上，
说明是系统性问题，该换参数重跑整个文档，而不是逐页手工修。

## 五、已经踩过的坑（供判读时参考）

| 现象 | 真相 |
| --- | --- |
| 覆盖率 0%，但内容看着都对 | 多半是 PDF 文字层把 `10⁶` 压成了 `106`、或用了繁体字形 |
| 【有差异】的提示里写着「解析里最像的是……」 | **不要因此放过**。实测某页原文同时有「加强型耦合」和「削弱型耦合」，解析只留了前者——因为「型耦合」三字重合，相似度够高，但两个词含义正好相反。必须回原图确认是不是同一个意思 |
| 数字缺失一个两位数，但内容看着都对 | 多半是页码，模型按规则正确丢弃了 |
| 报「数字缺失 10」而原文里找不到 10 | 原文有 `10BASE-T wall plate` 这类图片水印文字 |
| 整页只解析出 15% | 真实存在：模型遇到读不懂的公式时**跳过了整段**。提示词已针对性加强，这类页重解析一次通常就好 |
| 图片名张冠李戴（电感电路图出现在电容页） | 真问题，且会污染检索。提示词已把图类型限制成封闭词表 |
| 解析结果开头出现「电路理论（上）第18页」这种标题 | 页眉页脚被当成标题了，会污染章节元数据。提示词已修 |
