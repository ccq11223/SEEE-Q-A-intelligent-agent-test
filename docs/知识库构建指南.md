# 知识库构建指南

对应实施方案 §4.1 与 §7 阶段 0/1。这份文档回答：**我要做什么、怎么做、怎么算做完了。**

> 想要「一步一步照着做」的版本，先看 [操作手册.md](操作手册.md)。
> 这份文档侧重讲清每一步为什么这么做。

---

## 一、你需要准备什么

### 1. 资料（缺这个什么都做不了）

第一门课（电路理论（上））需要：

| 资料 | 大概量 | 可信级别 | 从哪来 |
| --- | --- | --- | --- |
| 老师串讲 / 中心往届 PPT | 主要部分，累计约 1000 页 | 一级 | 课程群、学长学姐、老师课件 |
| 老师划定的考点范围 | 几页到几十页 | 一级 | 老师或课代表 |
| 课本重点章节 | 按需 | 一级 | 教材扫描或 PDF |
| 典型例题 | 按需 | 二级 | 教材例题、习题课 |
| 往年试题与答案 | 若干套 | 二级 | 中心存档 |

先攒齐**第一门课**就好。资料不全也可以开始——知识缺口清单会告诉你缺什么。

### 2. 账号与密钥

照 [云平台与账号准备.md](云平台与账号准备.md) 开通 4 个账号，把 4 个值填进 `.env`。

### 3. 一台电脑

PPT 转图片、切块、向量化都在本机跑（方案 §6.1 形态 A）。
Windows + 桌面版 PowerPoint 的机器最省事（本仓库已针对这种情况优化）；
没有 Office 时先手工把 PPT 另存为 PDF 也能继续。

### 4. 时间

第一次跑通大约 **1 天**：装环境 + 试水 + 抽查。
全量 1000 页解析是机器在跑，**1-3 小时**，你可以去干别的。

## 二、建库到底在做什么

七个步骤，每一步都有明确产物。**记住一件事：解析质量是整个系统的天花板。**

| 步骤 | 做什么 | 命令 | 产物 |
| --- | --- | --- | --- |
| 1 | 资料登记与分级 | 手工编辑 `config/manifest.csv` | 资料台账 |
| 2 | 格式规范化 | `python -m pipeline render` | `data/work/<编号>/pages/*.jpg` |
| 3 | AI 结构化解析 | `python -m pipeline parse` | 逐页 Markdown + 整篇 `doc.md` |
| 4 | 人工抽查 | `python -m pipeline sample` | `sample_report.md` |
| 5 | 清洗与切块 | `python -m pipeline chunk` | `chunks.jsonl` |
| 6 | 向量化入库 | `python -m pipeline load` | `chunks` 表 / `chunks.jsonl` |
| 7 | 往年题处理 | （阶段 1 后段实现） | `questions` 表 |

`python -m pipeline run` 会把 2→6 一次跑完，这通常是你要用的命令。

### 关于资料分级（这一步别偷懒）

| 级别 | 含义 | 能不能被引用 |
| --- | --- | --- |
| 一级 | 课本重点、老师划定考点、中心往届串讲 PPT | 可以直接引用 |
| 二级 | 典型例题、我们自己生成的往年题解析 | 可以引用，但要标注 |
| 三级 | 网络来源 | **不能直接引用**，必须先人工审核升级为二级 |

代码里三级资料默认被排除在检索之外（`config/retrieval.yaml` 的 `max_trust_level: 2`）。
这是"防止错误知识输出"最省力的一道防线。

## 三、照着做：从零到跑通

### 第 0 步：装环境

```powershell
pip install -r requirements.txt
Copy-Item .env.example .env      # 然后编辑 .env 填四个密钥
python -m pipeline doctor        # 自检，缺什么它会直接告诉你
```

`doctor` 会逐项检查：配置文件、依赖、本机 Office 能力、四个密钥、存储后端、资料台账。
**全部打勾再往下走。**

### 第 1 步：数据库建表

照 [db/README.md](../db/README.md) 把 `db/migrations/*.sql` 在 Supabase SQL Editor 里执行。

⚠️ 建表这一步可以晚点做。先把 `config/pipeline.yaml` 里的
`storage.backend` 保持 `local`，整条链路照样能跑通（结果写成本地 JSONL）。
**建议先跑通再连数据库**，这样出问题时不用怀疑是网络还是代码。

### 第 2 步：登记资料

打开 `config/manifest.csv`（用 Excel 也行），参考 `config/manifest.example.csv` 填：

```csv
doc_key,course_id,doc_type,trust_level,filename,title,term,priority,notes
slide-ch01,circuit-theory-1,slide,1,电路理论_第01章.pptx,第01章 电路模型与电路定律,2026秋,1,往届串讲
```

几个约定：

- `doc_key` 自己起，全小写加连字符，**填了就不要再改**（它决定了缓存与切块的稳定标识）；
- `filename` 要和放进 `data/raw/` 的文件名一致；如果文件名太乱，
  也可以直接把文件重命名为 `<doc_key>.pptx`；
- `priority` 越小越先处理，0 是考点范围这种最该先看的。

填完用 `python -m pipeline manifest` 检查一遍，会列出每份资料的"文件状态"。

### 第 3 步：把文件放进 `data/raw/`

`data/` 整个目录不进 git（原始资料可能有版权问题，也不该塞进代码仓库）。

### 第 4 步：先跑 5 页试水（**这一步不能跳过**）

```powershell
python -m pipeline run --doc slide-ch01 --pages 1-5 --dry-run
```

跑完打开 `data/work/slide-ch01/doc.md`，**用眼睛看**：

- 公式是不是 LaTeX（`$...$`），下标上标对不对；
- 表格是不是还原成了表格；
- 图是不是变成了 `[图 第1页-1：...]` 这样的占位标记。

这一步的意义：解析质量差的话，后面所有回答都会错。
如果发现某类公式全部转错、或者整页内容丢失，**换模型或换参数重跑**，
而不是逐页手工修。试水花的钱不到一毛。

### 第 5 步：全量建库

```powershell
python -m pipeline run --doc slide-ch01        # 单份资料
python -m pipeline run --all                   # 该课程全部资料
```

看进度、看末尾的小结。中断了直接重跑——已解析的页会命中缓存，不会重复花钱。

### 第 6 步：人工抽查 5%（**这一步不能省**）

```powershell
python -m pipeline sample --all
```

生成 `data/work/<编号>/sample_report.md`，里面按风险排序列出了要重点看的页：
解析失败的页、有"不清晰"标记的页、同时含公式和图表的页。

抽查的正确用法：**找系统性错误**，不是逐页校对。
如果同一类错误出现三次以上，说明是系统性问题，换参数重跑整个文档。
发现问题就记进 `parse_errors` 表（`python -m pipeline` 的
`store.record_parse_error` 会写入，也可以直接在 Supabase 表编辑器里加行）。

### 第 7 步：切到云端数据库

前面几步如果用 `local` 后端跑通了，现在改 `config/pipeline.yaml`：

```yaml
storage:
  backend: postgres
```

然后只重跑入库那一步（渲染、解析结果、切块都在本地，不用重来）：

```powershell
python -m pipeline load --all
```

用 `python -m pipeline stats` 确认云端有内容了。

### 第 8 步：提问验收

```powershell
python -m pipeline search "节点电压法的适用条件"
python -m pipeline ask "为什么理想电流源不能开路？"
```

`search` 看召回：命中的页码对不对、相关度多少。
`ask` 走完整决策链，输出里会写清走了哪条分支：

- `kb` —— 有依据，回答带页码；
- `handoff` —— 没依据，转人工（同时记进知识缺口清单）。

验收标准（方案 §7 阶段 0）：**能从"提问"一路走到"回答带正确页码引用"。**

### 第 9 步：准备黄金测试集

建 30-50 题的固定题集放 `tests/golden/`，每题记录：
问题、期望命中的资料页、期望的结论要点。**其中必须有 10 道"资料里根本没有"的负样本。**

以后每次改提示词、换模型、补资料，都跑一遍这个题集，记录命中率与编造率。
这是判断"这次调教是变好了还是变坏了"的唯一客观依据（方案 §8.1）。

对齐方案 §1.4 与 §7 阶段 1：

- [ ] `python -m pipeline doctor` 全绿
- [ ] 课程核心章节 100% 有内容入库（`python -m pipeline stats` 看块数）
- [ ] 随机抽 20 个真实考点，至少 16 个能检索到正确课件页

## 五、常见问题

**Q：`run` 报"存在未解析页，已跳过切块与入库"，怎么办？**
说明有些页没解析成功。看上面的失败页提示，用
`python -m pipeline parse --doc <编号> --pages 3,7` 单独补跑。
确实是空白页的话，可以加 `--allow-partial` 跳过。
这个保护是故意的：避免用残缺内容覆盖已有知识库。

**Q：PPT 转图片失败了。**
本机 PowerPoint 打开这个文件后能正常显示吗？常见原因是文件被占用、
受保护视图未放行、或路径里有特殊字符。最省事的办法：在 PowerPoint 里
另存为 PDF，把 PDF 放进 `data/raw/`，把台账里的 `filename` 改成 PDF 文件名。

**Q：解析结果里公式全是乱码。**
检查是不是走了纯文本分支（`config/pipeline.yaml` 的 `parsing.mode`）；
默认 `vision` 是每页都送图，不该出现这种情况。
也可以换模型试试（见云平台文档第五节）。

**Q：改了提示词要重跑什么？**
不用重跑渲染和切块。改 `config/prompts.yaml` 后直接
`python -m pipeline parse --all` —— 缓存键包含提示词版本，只有受影响的页会重新调用模型。

**Q：忘了自己改过什么。**
所有可调内容都在 `config/` 下且纳入 git。`git log -p config/` 就是完整的调教历史。

**Q：花了多少钱？**
`data/out/qa_logs.jsonl`（或 `qa_logs` 表）里有每次问答的耗时与模型。
解析成本可以在百炼和硅基流动的控制台看用量。
